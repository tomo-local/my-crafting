# 0303: SELECT文のパース

- 元ページ: https://trialofcode.org/database/0303_parse_select/

## このステップで学ぶこと

- トークンと値のパース処理を組み合わせて、実際にSELECT文全体を構造化データにパースする
- 対応範囲は「主キーによる単一行クエリ」に限定する（例: `select a,b from t where c=1 and d='e'`）

## 要点

- パース結果を格納するデータ構造
  - `StmtSelect`: テーブル名・カラム列・キー条件を保持する構造体
  - `NamedCell`: カラム名とそのCell値のペア
- 基本戦略は「左から右へトークンを消費しながらデータ構造を組み立てる」という、トークナイザーと一貫した方針
- パース処理を役割ごとに分割している
  - `parseSelect()`: SELECT句とFROM句を処理し、対象カラムとテーブル名を取得
  - `parseEqual()`: `カラム=値` の形式をパース
  - `parseWhere()`: WHERE句を処理し、複数の等値条件をAND結合として扱う
- 文法上の制約
  - カラムリストはカンマ区切りで、`FROM` キーワードの出現で終了
  - WHERE句はANDで結合された複数の等値条件（`=`）のみサポート（OR・不等号等は非対応）
- 複雑な文法であっても、パース処理を細かい関数に分割することで管理しやすくなるという設計思想が強調されている

## 実装のポイント / 注意点

- 各パース関数はトークン列を消費した後、次に来るべきトークン（キーワードやシンボル）を期待値としてチェックし、想定外であればエラーを返すべき
- WHERE句を「等値条件の列」として扱う設計は、次ステップ（0305）で「主キーによる行特定」に直結する前提になっている点に注意（範囲クエリやインデックスは対象外、将来のステップで拡張予定）
- 前段（0302: 値のパース）で作った `parseValue` をそのまま `parseEqual()` 内で利用する形になる
- 次のステップ（0304）では、SELECT以外のSQL文（CREATE TABLE / INSERT / UPDATE / DELETE）へパース対象を拡張する
