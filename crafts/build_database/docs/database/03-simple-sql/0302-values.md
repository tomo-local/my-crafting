# 0302: 値（リテラル）のパース

- 元ページ: https://trialofcode.org/database/0302_parse_values/

## このステップで学ぶこと

- トークナイザーが切り出したリテラル文字列を、実際のGoの値（int64・文字列）に変換する処理を実装する
- 数値と文字列という2種類のデータ型に限定して、値のパースルールを設計する

## 要点

- 現時点で対応するデータ型は `int64` と文字列の2つのみ
- `parseValue` は先頭の1文字を見て解析方法を振り分ける
  - `"` または `'` があれば文字列としてパース
  - 数字または符号（`-`、`+`）があれば整数としてパース
- 整数のパースルール: 先頭に `-` または `+` を許可し、その後に数字が続く
- 文字列のパースルール（3つの要件）
  - クォート記号（`"` または `'`）で囲まれている
  - クォート内部に同じクォート文字を含めたい場合はバックスラッシュでエスケープする
  - バックスラッシュ自体を表現する場合もエスケープが必要
  - 例: `"isn\'t"` は `isn't` を表す
- ページ自体が「完全な実装には `\n` や `\xFF` のようなエスケープシーケンス対応が必要だが、学習の優先度上ここでは省略する」と明言しており、意図的にスコープを絞った簡略実装であることが前提

## 実装のポイント / 注意点

- 値のパースはトークナイザーの後段に位置し、「切り出された文字列トークン」を「型付きの値」に変換する責務だけを持たせるとよい
- エスケープ処理を実装する際は、バックスラッシュの直後の1文字を無条件に受け入れる（クォート文字かバックスラッシュ自体かを問わない）とシンプルに実装できる
- 本チュートリアルではスコープを絞っているため、`\n` 等の制御文字エスケープや数値以外の型（浮動小数点等）は将来的な拡張ポイントとして意識しておく
- 前段（0301: トークナイザー）で切り出したトークンを入力とし、次段（0303: SELECT文パース）ではこの値パース処理を組み込んで `WHERE b=1` のような条件式を組み立てる
