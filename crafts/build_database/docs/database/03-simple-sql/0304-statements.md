# 0304: 各種SQL文のパース

- 元ページ: https://trialofcode.org/database/0304_parse_stmt/

## このステップで学ぶこと

- SELECT以外のSQL文（CREATE TABLE、INSERT、UPDATE、DELETE）をパースできるようにする
- 複数種類のSQL文を1つの入口関数から適切なパーサーへ振り分ける仕組みを作る

## 要点

- 対応するSQL文とそれぞれの構造体
  - CREATE TABLE → `StmtCreatTable`（列情報と主キーを保持）
  - INSERT → `StmtInsert`（単一行の挿入のみ対応）
  - UPDATE → `StmtUpdate`（主キー指定での更新のみ対応）
  - DELETE → `StmtDelete`（主キー指定での削除のみ対応）
- 現段階のスコープは「主キーによる単一行操作のみ」に限定されている
  - 複合主キー（複数カラムからなる主キー）には対応する
  - WHERE句は主キーへのマッピングとして扱われる
  - インデックスや範囲クエリへの対応は後続ステップに持ち越し
- `parseStmt()` が中心的な入口関数となり、先頭のキーワードを見て対応するパーサーへ分岐する
  - 戻り値は `interface{}` 型とし、異なる文型（構造体）をまとめて返せるようにしている
- `tryKeyword()` は複数トークンからなるキーワード（例: `CREATE TABLE` のような2語のキーワード）にも対応できるよう拡張されている

## 実装のポイント / 注意点

- 文の種類ごとにパーサーを分け、`parseStmt()` は「振り分けだけ」に専念させることで見通しがよくなる（0303で確立した「機能ごとに関数を分割する」方針の延長）
- `interface{}` で複数の構造体を返す設計は、後続ステップ（0305）で型スイッチによる実行処理につながる前提になっている
- 主キー単位の単純操作に限定しているのは意図的なスコープ縮小であり、インデックス・範囲検索は45ステップシリーズの後半で扱われる予定
- 前段（0303: SELECT文パース）で確立したパース戦略・データ構造の設計方針をそのまま踏襲している
