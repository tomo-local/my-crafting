# 0600: アトミック更新（Atomic Updates）

- 元ページ: https://trialofcode.org/database/0600_atomic_data/

## このステップで学ぶこと

- これまでの「ログ + インメモリ配列」構成の限界を理解する
- ディスク上に永続化されたデータ構造へ進化させる方向性を把握する
- B+Tree と LSM-Tree という2つの実用的な選択肢の位置づけを知る

## 要点

- 現状の実装はインメモリDBに永続性（ログ）を足しただけであり、次の課題がある
  - データサイズがメモリ容量に制限される
  - ソート済み配列への挿入・削除はO(N)で非効率
- ディスク上のデータ構造として実用に耐えるのは事実上 B+Tree と LSM-Tree の2択
- どちらも「単純なソート済み配列」から段階的に進化させられる設計
- ディスク上の構造を更新する際にはアトミック性（更新途中でクラッシュしても壊れない）が課題になる
- 解決策の代表例として Copy-on-Write、ダブルバッファリング、物理ログ、LSM-Tree が挙げられている

## 実装のポイント / 注意点

- このステップ自体はコードを書くというより、これから向かう設計の全体像を示す位置づけ
- 次以降のステップ（SSTable構築・検索・マージ）は LSM-Tree 方向への具体的な一歩
- Webの簡易版は概要のみで、詳細な比較・実装根拠はフルブックに記載されている点に留意
