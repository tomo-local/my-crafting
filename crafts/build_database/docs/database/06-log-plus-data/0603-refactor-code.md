# 0603: コードのリファクタリング（Refactor Code）

- 元ページ: https://trialofcode.org/database/0603_mem_refactor/

## このステップで学ぶこと

- 新機能追加ではなく、次ステップ（マージソート・SSTable統合）に備えた内部構造の整理を行う
- メモリ内構造を独立した型として切り出し、将来のデータ構造置き換えを容易にする

## 要点

- 現状の `KV` 型は2つの配列を直接保持しており、SSTableを追加すると構造が複雑化する
- 改善案として、メモリ内構造を `SortedArray` 型に分離し、`KV` 型はそれを参照する構成に変更する
- `SortedArray` は `SortedKV` インターフェースを実装し、SSTable構築時の入力としてそのまま使えるようにする
- フィールドへの直接アクセスを禁止し、メソッド経由のアクセスに統一（カプセル化）
- `KVIterator` を `SortedArrayIter` にリネームし、名前から役割が明確になるようにする

## 実装のポイント / 注意点

- 本ステップは「動作変更なし」の純粋リファクタリングであり、外部から見た振る舞いは一切変えない
- `SortedArray` が持つべきメソッド: サイズ確認（`Size`）、イテレータ生成（`Iter`）、データ操作（`Get`/`Set`/`Del`）
- `Seek()` の戻り値も具体的な型からインターフェース `SortedKVIter` に変更し、SSTableのイテレータとも共通の型で扱えるようにする
- ここで型を整理しておくことで、次ステップ0604のマージソートやSSTable統合の実装がシンプルになる
