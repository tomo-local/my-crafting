# 0507: WHERE句での範囲クエリ

- 元ページ: https://trialofcode.org/database/0507_where_range/

## このステップで学ぶこと

- WHERE句で `a > 123` や `(a, b) > (123, 0)` のような範囲指定クエリをサポートする
- 既存の `DB.Range()` 機能とSQL解析層（式パーサ・評価器）を統合する

## 要点

- `RangeReq` 構造体を定義し、比較演算子（`StartCmp`/`StopCmp`）と開始値・終了値を保持することで範囲検索の条件を表現する
- 新規メソッド
  - `execCond()`: WHERE条件を範囲リクエストに変換する入り口
  - `makeRange()`: 条件式を解析して `RangeReq` を生成する
  - `parseTuple()`: `(a, b) > (1, 2)` のような複合キーのタプル構文をパースする
- SELECT/UPDATE/DELETEはすべて「WHERE条件を `makeRange()` で `RangeReq` に変換 → `Range()` を実行」という統一された流れで処理されるようになる
- `ExprTuple` 構造体で複合キーの範囲指定を表現し、`matchAllEq()`（0506）による単純な等価条件も内部的には範囲クエリとして統合される
- `matchRange()` が二項演算子の種類を判定し、`a > 1` のような単一条件や `AND` で結合された複合条件に対応する

## 実装のポイント / 注意点

- `OR` 結合は複数の `Range()` 呼び出しが必要になり、範囲の和集合・積集合を求める簡約化処理が煩雑になるため、このステップでは未実装
- 現状は単一範囲のみのサポートであり、複数条件の組み合わせ最適化は今後の課題として明示されている
- 等価条件（0506の `matchAllEq()`）と範囲条件（`matchRange()`）を同じ `RangeReq` の枠組みに統一している点が設計上のポイントで、SQLの条件式を一段抽象化された「範囲」概念に落とし込む考え方を理解することが重要
