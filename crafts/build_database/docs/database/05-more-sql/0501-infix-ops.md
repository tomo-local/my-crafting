# 0501: 中置式（二項演算）の表現

- 元ページ: https://trialofcode.org/database/0501_binop/

## このステップで学ぶこと

- SQLのWHERE句で「a = 123」のような固定形式だけでなく、`a > 123` や `(a, b) > (123, 0)` のような複雑な条件式を扱えるようにする土台を作る
- 式（expression）を木構造（AST）として表現する方法を理解する
- まずは優先順位を無視した最小限のパーサ（加減算のみ）を作り、次ステップ以降で拡張していく

## 要点

- 二項演算は `ExprBinOp` 構造体で表現する
  - `op`: 演算子種別（`OP_AND`, `OP_EQ`, `OP_GT`, `OP_ADD`, `OP_SUB` など）
  - `left`, `right`: 被演算子
- 被演算子は `interface{}` 型にすることで、以下の3種類を統一的に扱う
  - 文字列（カラム名）
  - `*Cell`（リテラル定数値）
  - `*ExprBinOp`（ネストした部分式）
- `parseAtom()` が最小単位（カラム名 or 定数）を解析し `interface{}` として返す
- `parseAdd()` が `parseAtom()` と演算子トークンの読み取りを繰り返し呼び出し、左結合で式木を構築する
  - 例: `a + b - 3` は `ExprBinOp{op: OP_SUB, left: ExprBinOp{op: OP_ADD, left: "a", right: "b"}, right: Cell{123}}` という左に偏った木になる

## 実装のポイント / 注意点

- `interface{}` を被演算子の型に使うのは、C/C++の `void*` に近い発想。型アサーションで後段の評価器が種別を判定する
- このステップの実装は演算子の優先順位を意識していない単純な左結合パーサであり、`+ -` のみを想定した仮実装
- 優先順位（`*` が `+` より強い等）や比較演算子・論理演算子への対応は次ステップ（0503, 0504）で行う
- ここで作ったASTのノード形状が、以降の評価器（0502）やSELECT/WHERE統合（0505〜0507）でそのまま使われるため、構造体設計を丁寧に理解しておくことが重要
