# 0700: LSM木入門

- 元ページ: https://trialofcode.org/database/0700_lsm_intro/

## このステップで学ぶこと
- LSM-Tree（Log-Structured Merge Tree）がどういう考え方なのかを理解する
- 汎用データベースの実装方式が大きくLSM-TreeとB+Treeの2択であることを知る
- これから実装していく2レベル構成（MemTable / SSTable）の全体像を掴む

## 要点
- LSM-Treeは特定のデータ構造の名前ではなく、「データ更新をマージ処理に置き換える」という設計方針・方法論である
- 構成要素の本質は「ソート済みキー・バリューの集合」であること。配列やツリーなどの具体的なデータ構造自体は本質ではない
  - 順序が不要であればハッシュテーブルを使う選択肢もあり得る
- 現時点の実装は2レベルで構成される
  - MemTable: 書き込みをログで永続化するインメモリ構造
  - SSTable: 一度書き込んだら変更不可（immutable）で、更新は新規ファイルへの置き換えとして行う
- 上位レベルほど優先度が高い（新しいデータが優先される）という原則があり、この考え方はkレベルまで一般化できる

## 実装のポイント / 注意点
- 「SSTableは不変」という制約は、以降のステップ（メタデータ管理・マージ処理）の設計に直結するため最初に押さえておく
- 2レベル構成は今後複数レベル（0703）に拡張されるので、最初から「レベル」という概念で設計しておくと後の変更がしやすい
