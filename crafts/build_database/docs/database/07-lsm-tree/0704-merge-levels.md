# 0704: レベル間のマージ処理

- 元ページ: https://trialofcode.org/database/0704_lsm_merge/

## このステップで学ぶこと
- ログをSSTableに変換し、複数レベル間でマージ（コンパクション）を行う仕組みを実装する
- レベルサイズの指数的な成長ルールに基づいたマージ判定ロジックを理解する

## 要点
- 新たに導入する2つのパラメータ
  - `LogShreshold`: ログ内に保持できる最大キー数。これを超えたらSSTableへ変換する
  - `GrowthFactor`: 隣接するレベル間のサイズ比率（各レベルが下位に比べどれだけ大きくなるかの倍率）
- `KV.Compact()`の処理フロー
  1. インメモリログが`LogShreshold`を超えていたら`compactLog()`でSSTable化する
  2. 各レベルについて`shouldMerge()`で、指数成長ルールに基づき「このレベルは肥大化しすぎていないか」を判定する
  3. マージが必要なレベルがあれば`compactSSTable()`で隣接する下位レベルと統合する
- 最終レベル（最下層）でのマージ時は、削除済みキーをその時点で完全に取り除く
  - `NoDeletedSortedKV`のようなラッパーでイテレータをフィルタリングし、削除フラグの立ったキーを出力から除外する

## 実装のポイント / 注意点
- 「指数成長ルール」により、レベルが上がるほどサイズが大きくなり、マージ頻度は下位レベルほど高く上位レベルほど低くなる。これがLSM-Treeの書き込み性能を支える設計
- 削除キーの完全な除去は最終レベルでのみ行うこと。中間レベルで消してしまうと、より上位にまだ有効な古いデータが残っている場合に矛盾が生じる
- このページの実装だけでは、まだ「いつCompactを呼ぶか」の自動トリガーがない。実用的なDBにするには書き込み時などにCompactを自動的に発火させる仕組みが今後必要になる
