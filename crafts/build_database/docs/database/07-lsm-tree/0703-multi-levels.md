# 0703: 複数レベルのSSTable

- 元ページ: https://trialofcode.org/database/0703_multi_levels/

## このステップで学ぶこと
- 単一のSSTableから、複数レベルに階層化されたSSTable構造へ拡張する
- 削除（deletion）を表現するための削除フラグ（tombstone）をSSTableフォーマットに導入する

## 要点
- 設計目的は次の3点
  - データ検索の効率化
  - コンパクション処理を段階的に実行できるようにすること
  - 削除されたキーの追跡管理
- データ構造の変更点: `KV.main` を単一の `SortedFile` から `[]SortedFile`（複数レベルの配列）に変更する
  ```go
  type KV struct {
      main []SortedFile // 複数レベル対応
  }
  ```
- SSTableフォーマットの拡張: キー長・値長に加えて「削除フラグ（1byte）」を持たせる
  - キー長（4bytes）+ 値長（4bytes）+ 削除フラグ（1byte）+ キー本体 + バリュー本体
- クエリ処理は複数レベルを横断して検索する必要があるため、`MergedSortedKV`のような仕組みで全レベルを統合的に走査して結果を返す
- 削除キーの記録は、最後のレベル（最下層）以外では必須
  - 最下層まで到達した削除キーは、それより古いデータがもう存在しないため物理的に消してよい
- `KV.Compact()`は新しく作ったSSTableを`KV.main[0]`（最上位＝最新レベル）へ挿入する

## 実装のポイント / 注意点
- 削除フラグを導入することで、「値が空だから削除」ではなく「明示的に削除された」ことを区別できるようにする点が重要
- 複数レベルを検索する際は、上位レベル（新しい）を優先して結果をマージする必要がある。0700で述べた「上位レベル優先」の原則がここで具体化される
- レベル間のデータ移動（マージ）そのものはこの段階では未実装で、次のステップ（0704）で扱う
