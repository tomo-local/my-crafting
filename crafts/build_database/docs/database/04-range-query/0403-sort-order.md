# 0403: 順序保持エンコーディング

- 元ページ: https://trialofcode.org/database/0403_ordered_encoding/

## このステップで学ぶこと

- KVストアではキーがバイト列として比較されるため、型付きデータ（整数・文字列など）の大小関係をバイト列の辞書式順序と一致させるエンコーディング方法を実装する
- キー用エンコーディングと値用エンコーディングを分離し、順序保持が必要な箇所とそうでない箇所を明確にする

## 要点

- KVストアの比較はバイト列同士の辞書式比較になるため、素朴なエンコーディングでは型付きデータの本来の順序が壊れる（例: 負の整数や文字列の特殊文字）
- スキーマに依存した比較ロジックを個別に実装すると結合度が上がるため、代わりに「ソート順を保つシリアライゼーション形式」を設計するアプローチを取る
- 既存の`Cell.Encode()`を`EncodeKey()`（KVキー用・順序保持が必要）と`EncodeVal()`（KV値用・従来通りでよい）に分割する
- int64の順序保持エンコーディング: `uint64(cell.I64) ^ (1<<63)` によって符号ビットを反転させ、負の値を含めた大小関係をバイト列の辞書式順序に一致させる
- 文字列はヌル終端方式を採用しつつ、区切り文字と衝突しないようエスケープする：`0x00 → 0x01 0x01`、`0x01 → 0x01 0x02`

## 実装のポイント / 注意点

- 浮動小数点数は整数と異なり、負の値の順序が単純なビット反転では正しくならない点に注意（0201で扱った内容を参照）
- 複数カラムをこの方式でシリアライズして連結すれば、タプル比較のような複合キーの順序保持が自然に成立する
- 次の0404では、この順序保持キーを前提にKVペアから行（Row）への変換・走査を実装する
