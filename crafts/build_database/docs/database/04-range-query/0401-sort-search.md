# 0401: ソートと検索

- 元ページ: https://trialofcode.org/database/0401_sort_search/

## このステップで学ぶこと

- 単一行のキー検索しかできなかったKVストアを、テーブル全体のスキャンや範囲クエリに対応させる準備をする
- ソート済みデータに対するバイナリサーチの実装を通じて、以降の範囲クエリ・ORDER BYの土台を作る

## 要点

- テーブルスキャン・範囲クエリ・ORDER BYは、本質的にはすべて「ソート順に走査する（iterate in sorted order）」という同一の操作である。範囲クエリ（`a > 123`）はテーブルスキャン（`-∞ < a < +∞`）の特殊ケースとみなせる
- データ構造をmapベースから配列ベース（`keys [][]byte` / `vals [][]byte`）に変更する。これは将来LSM-Treeへ発展させるための過渡的な形
- Get操作は`BinarySearchFunc`のような標準ライブラリ関数で実装できるが、アルゴリズムの理解のために自前実装も推奨される
- キーが見つかった場合は`ok=true`、見つからない場合は挿入位置（そのキーが挿入されるべき位置）を返す設計にする

## 実装のポイント / 注意点

- 現段階では全データをメモリに載せる前提（ディスクベースの実装はまだ扱わない）
- バイナリサーチは見た目がシンプルな割に、境界条件（探索範囲の終端、見つからない場合の挿入位置）を誤りやすい領域なので慎重に実装する
- 次の0402ではKVイテレータを導入し、この配列ベース構造を効率的に走査する仕組みを作る
