# 0404: 行イテレータ

- 元ページ: https://trialofcode.org/database/0404_row_iterator/

## このステップで学ぶこと

- KVイテレータの上に、KVペアを行（Row）データへデコードする`RowIterator`を構築する
- テーブルごとにプレフィックスで分離されたキー空間を正しく走査するための境界チェックを実装する

## 要点

- `RowIterator`は`Seek()`（プライマリキー以上の最初の位置を返す）、`Valid()`（走査終了判定）、`Row()`（現在の行を取得）、`Next()`（前進）から構成される
- 各テーブルのキーはプレフィックスで区切られているため、スキャン中に「現在のキーが対象テーブルに属しているか」を都度検証する必要がある。属さない場合は走査を終了する
- プレフィックス検証は、キーの先頭が `schema.Table + "\x00"` と一致するかで判定する
- キーがテーブル範囲外に出た場合を表すため、`DecodeKey()`が専用の`ErrOutOfRange`エラーを返すよう拡張する
- デコード結果（行データ）を`RowIterator`内にキャッシュし、`valid`フラグで管理することで、毎回のデコード負荷を避ける

## 実装のポイント / 注意点

- `RowIterator`構造体はスキーマ参照・内部の`KVIterator`・`valid`フラグ・デコード済み行データを保持する形になる
- `decodeKVIter`の詳細実装や`Seek()`本体のロジックは読者への演習課題として残されている部分があるため、自前で設計判断が必要になる
- 次の0405では、この行イテレータを使って実際の範囲クエリ（開始・終了条件付きのスキャン）を実装する
