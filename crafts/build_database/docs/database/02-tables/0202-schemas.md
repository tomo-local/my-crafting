# 0202: スキーマ

- 元ページ: https://trialofcode.org/database/0202_schema/

## このステップで学ぶこと

- テーブルの構造（テーブル名・カラム一覧・主キー）を表す`Schema`と`Column`の設計を理解する
- 主キーがKVストアのキーとバリューにどう対応するかを把握し、KVストアの上にOLTPデータベースを構築する仕組みを理解する

## 要点

- `Schema`構造体はテーブル名・カラム情報・主キーとなるカラムの位置を保持する
- `Column`構造体はカラム名と型情報（0201で定義した型）を保持する
- 主キーは行を一意に識別するもので、1つ以上のカラムで構成できる（複合主キー）
- 主キーのカラム群がKVの「キー」部分を形成し、非主キーのカラム群が「バリュー」部分を形成する。この対応関係によってKVストアがリレーショナル（OLTP）データベースの基盤になる
- セカンダリインデックスも同じKV構造（キー＋バリュー）で実装できるが、主キーは必須であるのに対しセカンダリインデックスは任意である点が異なる
- テーブル名をキーのプレフィックスとして使う場合、テーブル名同士の衝突を避けるためヌルバイト（0x00）をセパレータとして挟む

## 実装のポイント / 注意点

- 本番実装ではテーブル名の代わりに整数IDをプレフィックスに使うと、省スペース化とテーブルリネームの両方が実現できる（学習実装では簡略化のためテーブル名で代用してよい）
- 例として`Link`テーブル（時刻・送信元・宛先カラムを持つ複合主キー）のスキーマ定義が示されており、複合主キーの扱いを具体的にイメージする材料になる
- 行全体のエンコード/デコード関数のシグネチャがここで導入され、0201のセル単位のエンコードを組み合わせて行単位のシリアライズを行う流れにつながる
