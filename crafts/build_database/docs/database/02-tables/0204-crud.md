# 0204: CRUD API

- 元ページ: https://trialofcode.org/database/0204_db_crud/

## このステップで学ぶこと

- 主キーに基づくCRUD（insert/select/update/delete）操作を、これまで作ったスキーマ・エンコード・更新モードを組み合わせて実装する
- `DB`構造体がKVインターフェースをどのようにラップしてライフサイクル管理・CRUDメソッドを提供するかを理解する

## 要点

- insert/select/update/delete の4操作に対応させる形で5つのメソッド（Insert/Upsert/Update/Select/Delete）を実装する
- `DB`構造体は内部でKVインターフェースに依存し、Open/Closeでライフサイクルを管理する
- Select/Deleteは主キーを含む行（キー部分のみで十分）を入力として受け取る
- Insert/Upsert/Updateは主キー＋非主キーを含む完全な行データを入力として要求する
- Insertの実装例: 行を主キーとバリューにエンコードし、`KV.SetEx()`を`ModeInsert`で呼び出して保存する。Upsert/Updateも同様に`SetEx`のモードを切り替えるだけで実現できる

## 実装のポイント / 注意点

- ここで実装するのは主キーによる単一行アクセスのみで、これは基本機能に過ぎない
- 今後のステップで追加される予定の機能として、フルテーブルスキャン・インデックスを使ったクエリ・範囲クエリ・フィルタリングなどが挙げられている
- 0202のスキーマ（行のエンコード/デコード）と0203の更新モードを正しく組み合わせられていれば、CRUD実装自体は薄いラッパーになるはず。もし複雑になっている場合は前段の設計を見直す
