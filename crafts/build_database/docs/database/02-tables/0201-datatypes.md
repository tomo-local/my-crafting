# 0201: データ型

- 元ページ: https://trialofcode.org/database/0201_data_types/

## このステップで学ぶこと

- KVストアの上にテーブル（Excelのようなカラム構造）を実装するための第一歩として、セルのデータ型を設計する
- 整数・文字列という異なる型を1つの構造体で扱い、バイト列へエンコード/デコードする方法を理解する

## 要点

- セルは型タグ（`TypeI64` / `TypeStr`）と、実体を格納するフィールドを持つ`Cell`構造体として表現する
- Goにはunion型がないため、両方の型のフィールドを同時に持たせることになり、メモリの一部は無駄になる（学習用実装として許容）
- `int64`はリトルエンディアンでエンコードする。現代の主要CPU・データ形式ではリトルエンディアンが主流であり、ネットワークプロトコル（ビッグエンディアン）とは異なる文脈であることに注意
- 符号付き整数と符号なし整数は、ビット表現（2の補数）が同一であるため、エンコード時に変換処理は不要。最上位ビットが符号を表し、+0/-0の重複表現を避けられる
- 文字列（バイト列）は「4バイトの長さ + データ本体」という長さプレフィックス形式でエンコードする

## 実装のポイント / 注意点

- `Encode()`は既存のスライスに追記する形にすることで、メモリ再利用を意識した実装にする（都度新規スライスを作らない）
- `Decode()`は消費しきれなかった残りのバイト列を返すようにし、複数セルを連続的にデコードできる設計にする
- ここで定義するエンコード形式は、次のステップ（スキーマ、CRUD）で行全体のシリアライズの基礎になるため、型の追加・変更がしやすい構造にしておく
